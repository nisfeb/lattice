# Passes: build plan and record

Spec: `docs/superpowers/specs/2026-11-11-passes-design.md`. Branch: task/5j6hcsko. Each phase is one or more commits, built with `scripts/hoon-build.sh check` (every file a vase) before it is committed.

## Phase 1: the pure libs

- `code/lib/lattice-pass.hoon`: the pass, offer, sale and payment types; `+live`, `+group-ships`, `+extend`, `+refund`, `+due`, `+next-wake`, `+prune`, `+summary`, `+sane-offer`, `+cashu-a`, `+mint-same`, `+cookie-code`.
- `code/lib/lattice-cashu.hoon`: furum's `lib/cashu.hoon`.
- `code/lib/lattice-stripe.hoon`: register's `register-stripe` and `register-http`.
- `code/lib/lattice-btcpay.hoon`: armillary's `armillary-btcpay`.
- Suites in `tests/lib/` for all three: `scripts/offline-tests.sh lattice-pass lattice-cashu lattice-stripe lattice-btcpay`.

Done.

## Phase 2: paid boards for ships

- The writer's `[%pass pass-act]` (`+apply-pass`): offers, grants, refunds, the lapse sweep on a `/pass-due` behn wake, and the read group kept as roster plus live ship passes (`+pass-group`).
- The post gate in `+forum-remote-apply`: a live `%post` pass posts as a poster; a `%read` pass is refused with its own note.
- The pay fiber `/passes/pay/<id>` (`+run-pay`), ecash and Lightning through the offer's mint, ported from furum; the wallet; the `%pass-buy` poke on `/forum.sig`; the buy page on a denied remote board.
- The owner's JSON routes (`/passes`, `/pass-offer`, `/pass-gift`, `/pass-refund`, `/pass-wallet`) and the Passes section of the mod page.
- `scripts/pass-matrix.sh`.

Done, except a ship-to-ship purchase, which is built but not run on two ships.

## Phase 3: the open web

- The buy page on a private board, `/pass/buy`, `/pass/state`, `/pass/use`, the cookie and the hashed code.
- Card: `/pass/card`, `/pass/return`, `/hooks/stripe`, the Stripe key at `/passes/secrets`.
- `scripts/pass-pay.sh` against a nutshell test mint.

- Bitcoin through BTCPay (`lib/lattice-btcpay`, armillary's), `/pass/bitcoin`, `/hooks/btcpay` with its signature, and both rails for ships through `/passes/open/<tok>`. The rail settings at `/pass-settings` and on the mod page.
- `scripts/pass-rails.sh` against `scripts/fake-rails.py`.

Done, except the real Stripe and BTCPay, which need the owner's test keys, and a ship paying another ship's host by any rail, which needs two ships.
